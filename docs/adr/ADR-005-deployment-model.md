# ADR-005: Deployment Model

**Status:** Accepted · **Date:** 2026-06-12 · **Updated:** 2026-06-14 (host migration)

> **2026-06-14 — Production migrated linuxg6 → linuxg3.** Same model (Docker Compose, only app
> exposed on 127.0.0.1:3180, Cloudflare tunnel, direct SSH push to a bare repo). What changed:
> host is now **linuxg3** (12c/31GB/AVX, idle — far better than g6); deploy remote is
> `git push linuxg3 main`; the tunnel is g3's **dashboard-managed** token tunnel
> `97dd7bda-d886-48aa-9b1f-e80779ad7baf` (ingress configured in the CF dashboard, no local
> config.yml). Migration was a lift-and-shift: rebuild images on g3, `mongodump`/`pg_dump` →
> restore (verified parity), cutover via CF, then g6 analytikul stack fully removed. g3's Docker
> data-root is on a slow disk → use the client hotfix path (see architecture.md) for client-only
> changes instead of the 30-45 min full build.

## Context
Need to ship Analytikul to production on Lacy's existing infrastructure (linuxg6) and serve it at
analytikul.ai, without disrupting other sites on the shared host.

## Decision
Docker Compose stack (`docker-compose.prod.yml`) on linuxg6. **Only the app container is exposed**
(127.0.0.1:3180→3080); every other service stays on the private compose network — no public ports.
Public routing via Cloudflare **dashboard-managed** tunnel (connector `Linuxg6-AI`, route
`analytikul.ai → http://localhost:3180`), www→apex 301. Code reaches the server by **direct SSH
push** to a bare repo (`~/analytikul.git`), checked out at `~/analytikul`. Deploy =
`git push linuxg6 main` then `scripts/deploy.sh` (preflight env/port checks → build app+adapter →
`up -d` → health-check loop). Production `.env` generated by `scripts/gen-prod-env.sh` (fresh
secrets, never dev values).

## Alternatives Considered
- Push to GitHub then pull on server — rejected by user (direct SSH only; do not create/push new
  GitHub repos without explicit naming). Empty `phoenixtekk/Analytikul-One` repo was created then
  abandoned.
- pm2/native Node — rejected; Docker matches the rest of the stack and isolates the agent runtime.
- Editing cloudflared config.yml on disk — rejected; **user manages all Cloudflare in the web
  console**. Surface exact records, never edit tunnel/DNS files.

## Consequences
+ Reproducible, isolated, only one port exposed; other host sites untouched (except a one-time
  Docker daemon restart that bounces all containers — requires user approval).
+ Simple deploy loop the user can run too.
− linuxg6 builds are slow (no AVX, modest CPU; app image 20-40 min). Host-network builds required
  (broken default-bridge DNS). mongo:4.4 pin required (no AVX). See architecture.md quirks.
