## Known issues and follow-ups, ranked

### 1. **Phase 2 docker CLI gap** — per-task ephemeral containers not yet operational

**State**: tonight's `activate-gvisor-sandbox.sh` run succeeded in rebuilding the
hermes-adapter image and standing up the `docker-socket-proxy` service. The
smoke test (`docker run --runtime=runsc alpine:3`) FAILED because `which
docker` returns missing in the new container.

**Root cause**: the Dockerfile installs the `docker.io` package on this
Debian/Ubuntu base, which on this distro contains the *daemon* binary
(`/usr/bin/docker-init`) but **not** the CLI (`/usr/bin/docker`). The actual
CLI lives in the `docker-ce-cli` package from Docker's official apt repo.

**Fix** (~1 hour next session):

```dockerfile
# services/hermes-runtime/Dockerfile — replace the docker-cli line with:
RUN install -m 0755 -d /etc/apt/keyrings && \
    curl -fsSL https://download.docker.com/linux/debian/gpg \
      | gpg --dearmor -o /etc/apt/keyrings/docker.gpg && \
    echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
      https://download.docker.com/linux/debian $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
      > /etc/apt/sources.list.d/docker.list && \
    apt-get update && apt-get install -y --no-install-recommends docker-ce-cli
```

Then `cd ~/analytikul && docker compose -p analytikul -f docker-compose.prod.yml build hermes-adapter` on g3, recreate the adapter, re-smoke-test.

**Impact today**: code execution still works via the Phase 1.5 subprocess
path inside the adapter container (under runsc at the daemon level). Per-task
isolation is the goal; we're operating on "in-adapter sandboxing" until the
CLI is installed.

## Deployment fragilities to remember

Captured in
`C:\Users\lacy.phoenixtekk\.claude\projects\G--VisualStudioCode-Analytikul-One\memory\deploy-fragility-warning.md`,
but summarized here for portability:

1. **Force-recreate wipes docker-cp hotfixes** on analytikul-app — dist,
   `api/server/index.js`, `api/server/routes/analytikul.js`. After ANY
   `--force-recreate`, re-push these or rebuild image.

2. **index.html is cached at server startup**
   (`api/server/index.js:175` does `fs.readFileSync` once). After every
   dist redeploy, `docker restart analytikul-app` — pure tar/cp is not
   enough.

3. **`librechat.yaml` is gitignored**. Changes live only locally and inside
   the container. After force-recreate the in-container yaml reverts to
   image-baked.

4. **`LIBRECHAT_CODE_BASEURL` is set via index.js runtime injection** — same
   docker-cp fragility tier. After force-recreate, the env override is gone
   until index.js is re-pushed.

5. **Phase 2 cross-net bridge**: `docker network connect vllm_default
   analytikul-app` is wiped by force-recreate. Re-run after any app recreate.

6. **`/app/.env` is empty** — production env comes from
   `docker-compose.prod.yml` `environment:` blocks. Adding a new env var the
   proper way requires editing compose + force-recreate (which then loses
   all of the above unless rebuilt-from-source).
